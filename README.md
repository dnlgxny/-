## 一、怎么用（三步）

```bash
cd ~/WorkBuddy/开源/工作台

python3 拉数据.py        # ① 拉数据（可选，数据已就绪）
python3 生成工作台.py     # ② 生成 HTML
open 工作台.html         # ③ 打开
```

**日常只需第 ③ 步**——`工作台.html` 是自包含单页（内联 ECharts + 内联数据），双击即用，无需联网、无需服务器。

仅当要**刷新数据**时才需重跑 ①②。

## 二、页面结构（三层交互）

```
第①层  指数列表
        纳斯达克100（可点）｜标普500🩶｜红利低波🩶｜上证指数🩶
   ↓ 点「纳斯达克100」
第②层  上：指数走势图（2002-10-09 ~ 至今，默认**全区间**显示，含 A/B/C 回撤阴影带）
        　 下方「可选数据」面板：13 项可多选叠加
        下：6 类指标卡（共 26 张）
   ↓ 点有「可点曲线」标记的卡片
第③层  主体图替换为该指标曲线（**用指标自身时间轴**）；NDX 走势作为背景线
```

### 2.1 指数走势图 · 多选（第②层）

「可选数据」面板共 **13 项**，按量纲分组、点选即叠加：

| 量纲组 | 可选数据 |
|---|---|
| 指数点位（左轴） | NDX 收盘、MA250、MA500 |
| 比率 | r500、r250 |
| 振荡/情绪 | RSI(14)、CNN 恐慌贪婪 |
| 波动率 | VXN、VIX |
| 估值 | PE-TTM、PB、ROE、股息率 |

- **同量纲共用一条 Y 轴**；不同量纲各自分配到独立右轴（错位排列），**不会互相压制**
- **鼠标悬停一次列出全部已选数据**（缺值显示 `—`）
- 选择结果**自动记住**（localStorage），下次打开保持
- 「恢复默认」按钮可重置为 NDX + MA250 + MA500

### 2.2 量纲同轴规则（重要）

NDX、MA250、MA500 **共用左轴**，因此三者的**相对高低是真实的**：
2026-10-14 读数 NDX 29950.82 > MA250 27216.28 > MA500 24423.70。

⚠️ 其他指标（PE/RSI/VXN 等）与指数**量纲不同**，强制同轴会互相压扁，
故分到独立右轴——此时图例会标注「独立刻度·仅参考形态」。

**每张指标卡**：
- 左上角标 `可点曲线` 或 `仅当期`
- 点 `?` → 弹出**白话解释**（这是什么 / 怎么读 / 当前位置 / 数据说明 / 注意事项）
- 底部印 **来源 + 数据日期**

导航栏 `② 待定` `③ 待定` 为模块 2/3 **灰字占位**（名称待定）。

## 五、四条必须知道的口径限制

1. **禁止跨口径比大小**：NDX 的 PE 三家不同源 —— 蛋卷 30.74（10-13）／Siblis 35.24（2026-06-30）／Nasdaq 官方 35.23（2026-06-30）。
2. **估值序列起点 2016-10**，覆盖不到 2002（图上已留白并标注「非 2002」）。
3. **波动率两口径不可比**：VXN/VIX 是「隐含波动」（期权预期）；年化波动率是「已实现波动」（历史）。
4. **QDII 净值天然滞后 1 日**（本页为指数口径，不受影响）。

## 六、更新数据

### 6.1 自动更新（已配置，无需手动）

**两层保障**：

| 层 | 机制 | 时间 | 依赖 |
|---|---|---|---|
| **主** | **GitHub Actions 定时**（云端） | 每周一至五 **09:30 / 11:30 / 14:30** | ❌ 不依赖本机开机 |
| 备 1 | 本机 launchd | 每周一至五 **09:00** | 需电脑开机 |
| 备 2 | DSH 会话内提醒 | 每周一至五 **09:30** | ✅ 需 DSH 运行 |

⚠️ **为什么云端设 3 个时间点**：GitHub 官方明确 `schedule` **不保证准时**
（高峰期可延迟一小时以上）。设多个点提高成功率，配合「数据未变则跳过」保证幂等。

**launchd 任务**
- 标识：`com.qumingtainanle.openwork.daily`
- 配置：`~/Library/LaunchAgents/com.qumingtainanle.openwork.daily.plist`
- 执行：`工作台/每日更新.sh`（拉数据 → 重新生成 HTML，约 **13–15 秒**）
- 日志：`logs/每日更新.log`（超 2MB 自动截断）

**手动管理命令**
```bash
# 查看状态
launchctl list | grep openwork

# 立即触发一次（验证用）
launchctl start com.qumingtainanle.openwork.daily

# 暂停 / 恢复
launchctl unload ~/Library/LaunchAgents/com.qumingtainanle.openwork.daily.plist
launchctl load -w ~/Library/LaunchAgents/com.qumingtainanle.openwork.daily.plist

# 看日志
tail -20 logs/每日更新.log
```

⚠️ **电脑未开机时不会补跑**（`RunAtLoad` 设为 false）。若长期不开机，手动执行 6.2 即可。

### 6.2 手动刷新

```bash
cd ~/WorkBuddy/开源/工作台
./每日更新.sh              # 一键（推荐）
# 或分步：
python3 拉数据.py && python3 生成工作台.py
```

### ⚠️ FRED 封锁说明

`fred.stlouisfed.org` 被**主机名级封锁**（HTTP 000，换 IP 无效）。当前对策是**双源拼接**：

| 序列 | 历史部分 | 最新部分 | 拼接校验 |
|---|---|---|---|
| NDX | FRED 本地缓存（1986 起） | **腾讯 `us.NDX`** | 重叠 1999 日最大差异 **0.010** |
| VXN | FRED 本地缓存（2001 起，覆盖 2002） | **CBOE `VXN_History.csv`** | 重叠 4298 日差异 **0.0000** |

`拉数据.py` 会自动：① 读本地缓存 → ② 拉替代源 → ③ **校验重叠期一致性**（差异超阈值则放弃拼接）→ ④ 只追加更新的日期。
**卡片上的来源会如实显示拼接情况**，例如「FRED NASDAQ100（本地缓存）+ 腾讯 us.NDX 补 1 日」。

后台任务 `../fred_同步.py` 每 15 分钟探测一次 FRED，解封后会自动切回单源；日志见 `../cache-长序列/_fred_sync.log`。

## 八、交付自检结果（2026-10-14）

| 项 | 要求 | 实际 | 结果 |
|---|---|---|---|
| E1 | `node --check` 内联 JS | 通过 | ✅ |
| E2 | Edge headless 渲染 + 逐页看过 | 5 张截图核对 | ✅ |
| E3 | 回撤 A/B/C = 10/13/22 | 10/13/22，阴影带 45 段 | ✅ |
| E4 | 时间轴起点 2002 | 2002-10-09 ~ 2026-10-13 | ✅ |
| E5 | 卡片印来源+日期 | 抽查 3 张正常 | ✅ |
| E6 | 占位灰字不可点 | 模块2/3 + 3 指数均灰字 | ✅ |

**开发中修掉的问题**：
1. **TDZ 崩溃**：`METRICS` 初始化时引用了尚未定义的 `D.vxnSt52` → 整个脚本中断（页面空白）。已把统计量计算提前。
2. **ROE 单位不一致**：卡片显示 31.52%，曲线画 0.3152。已统一为百分数。
3. **背景灰度线过淡**：`#cbd5e1` → `#94a3b8`，提高可辨识度。
4. **🔴 周频指标曲线画不出来**（用户报障）：蛋卷 PE/PB/ROE 日期是**周日**（如 2016-10-23），与 NDX **交易日轴**不匹配——515 点里仅 50 点落在轴上（9.7%），又被 `connectNulls:false` 切断 → 图上只剩孤点。
   **修法**：指标图改用**指标自身时间轴**（周频连续），不再强行对齐日频轴。
5. **🔴 MA 视觉错位**（用户报障「MA 数值比历史极值高」）：原实现把背景 NDX 放在**隐藏的第二 Y 轴**，与 MA **各自独立缩放** → MA 线看起来全程浮在 NDX 上方，与真实数据（NDX > MA500）相反。
   **修法**：同量纲强制同轴——NDX/MA250/MA500 共用左轴，真实比例。
6. **默认视图被截断**：`dataZoom` 起点为 70%（只看 2020 年后），与标题「2002 起」不符，且大部分回撤带看不见。已改为 **0–100% 全区间**。
7. **🔴 每日更新失败的真正原因（校验写死段数）**：workflow 里把回撤段数写死成
   `assert c == {A:10,B:13,C:22}`，但 **C 级段数会随数据增长** ——
   实测已从 22 变成 23（2026-10-06 → 2026-10-16 新形成一段 −6.5% 回撤）。
   ⇒ 定时一跑必然 assert 失败 → 整个工作流失败。
   **修法**：改为「结构与量级」校验（起点 / 交易日数 / 各级下限 / 明细与汇总一致），**不写死具体数值**。
